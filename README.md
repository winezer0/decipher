# decipher

decipher 是一个基于 Go 语言编写的高性能本地哈希解密工具。它利用预计算（彩虹表原理）的方式，通过构建本地哈希缓存库来实现快速的哈希查找与解密。支持多种常见的哈希算法，并内置了常用的弱口令字典。

## 1. 功能介绍

- **高性能解密**: 利用 Go 语言的并发特性，快速进行哈希计算和匹配。
- **静态哈希算法**: 内置 30+ 种静态哈希算法，涵盖 MD5, SHA 系列, MySQL, NTLM, MSSQL等。
- **动态哈希算法**: 支持bcrypt等明文和密文无对应关系的动态hash算法。
- **解密算法支持**: 支持BASE64、DES、AES等某些CMS的密码解密算法。
- **预计算缓存解密**: 支持将自定义字典和内置字典预先计算为哈希表（Cache），极大提升后续的解密速度。
- **动态计算解密**: 支持运行时动态验证哈希值，无需预计算所有可能的哈希组合。
- **Salt支持**: 支持带 Salt 的哈希计算和解密，可灵活配置 Salt 组合模式。
- **内置字典**: 仅集成部分简单常用弱口令，更多字典需要用户添加。
- **算法猜测**: 支持通过hash和salt解密从而实现算法猜测。
- **结果导出**: 支持将解密结果导出为 CSV 或 JSON 文件。

## 2. 程序运行逻辑与解密原理

decipher 的核心原理是**预计算缓存碰撞 + 实时hash计算 + 可逆算法解密**。

### 解密阶段详解

#### 阶段 1: 预计算缓存破解 (Predb Crack)

- **适用算法**: 静态哈希算法 (MD5, SHA1, SHA256等)
- **原理**: 使用预先计算的哈希缓存文件进行快速匹配
- **优势**: 速度极快，适合常见哈希算法
- **控制**:
  - 默认执行预计算破解
  - `--npc` 禁用预计算破解，对支持缓存的静态算法也使用动态破解
- **执行条件**:
  - 存在预计算算法且未被 `--npc` 禁用 → 执行预计算破解
  - 被 `--npc` 禁用 → 直接使用动态破解 (RunHashCrack)

#### 阶段 2: 动态哈希破解 (Dynamic Crack)

- **适用算法**:
  - 静态哈希 (计算速度快)
  - 动态哈希 (bcrypt等，明文密文无固定关系)
- **原理**: 使用字典文件进行实时哈希计算验证
- **优势**: 无需预计算，灵活性高
- **控制**:
  - `--ndc` 禁用动态破解
  - `--nhc` 禁用运行时缓存
- **执行条件**:
  - 预计算破解失败后执行
  - 未被 `--ndc` 禁用
  - 包含静态或动态算法

#### 阶段 3: 加密解密阶段 (Decrypt)

- **适用算法**: 可逆加密算法 (BASE64, DES, AES等)
- **原理**: 使用密钥字典进行解密测试
- **优势**: 可解密某些CMS的加密密码
- **执行条件**:
  - 在预计算和动态破解失败后执行
  - 存在可逆加密算法

## 3. 命令行参数说明

使用 `./decipher -h` 可查看帮助信息。以下是参数的中文详细介绍：

### 基础输入输出

- `-i, --hashes`: 输入要解密/加密/识别的哈希值或明文，或包含内容的文件路径（每行一个）。
- `-o, --output`: 指定输出目录路径（默认当前目录）。
- `-O, --output-type`: 指定输出格式，可选 `csv` 或 `json`（默认为 `csv`）。

### 操作模式 (`-m, --mode`)

- `dec` (默认): 解密模式。对输入的哈希值进行破解。
- `enc`: 加密模式。对输入的明文进行哈希计算。
- `add`: 添加模式。将指定的字典和 Salt 添加到预计算数据库 (Pre-db)。
- `id`: 识别模式。识别输入哈希值的可能算法类型。

### 缓存构建与字典管理

- `-p, --plains`: 指定自定义明文字典文件路径或直接输入字典字符串。
  - 在 `add` 模式下：用于生成预计算数据。
  - 在 `dec` 模式下：作为动态破解的字典源。
  - 在 `enc` 模式下：作为加密用的明文字典。
- `-s, --secrets`: 指定 Salt/密钥 字符串或包含 Salt 的文件路径。
  - 在 `add` 模式下：与字典组合生成带 Salt 的哈希预计算数据。
  - 在 `dec` 模式下：作为动态破解的 Salt/密钥 字典。
  - 在 `enc` 模式下：作为加密用的 Salt/密钥。
- `--sp, --salt-prefix`: 在使用 Salt 前添加前缀字符串（默认为空）。
- `--ss, --salt-suffix`: 在使用 Salt 后添加后缀字符串（默认为空）。
- `--pp, --pass-prefix`: 在使用明文密码前添加前缀字符串（默认为空）。
- `--ps, --pass-suffix`: 在使用明文密码后添加后缀字符串（默认为空）。
- `-w, --workers`: 指定并发工作线程数（默认为 0，自动适配 CPU 核心数）。
- `-C, --cc`: 清空缓存目录下的所有文件（慎用）。
- `-D, --dc`: 对 hash 预计算缓存文件进行去重整理。
- `-R, --rr`: 清理字典字符串生成的临时文件。
- `--npc`: 禁用预计算缓存破解（predb），对支持缓存的静态算法也使用动态破解。
- `--ndc`: 禁用动态计算破解（dynamic crack）。
- `--nhc`: 禁用运行时哈希缓存，不读取也不写入动态缓存。

### 算法控制

- `-a, --algos`: 指定使用的哈希算法关键字（例如 `md5`, `sha1`, `bcrypt`）。支持部分匹配，会自动匹配包含指定关键字的所有算法。如果不指定，默认使用所有可用算法。
- `-L, --list`: 列出当前支持的所有哈希算法。

### 其他选项

- `--predb-dir`: 指定预计算数据库存储目录（默认 `decipher_db`）。
- `--run-cache-dir`: 指定运行时动态缓存目录（默认 `decipher_cache`）。
- `--failure-cache`: 指定解密失败记录文件（默认 `decipher.failure.csv`）。
- `--concat-symbol`: 指定哈希部分的连接符（默认 `:`）。
- `-v, --version`: 显示程序版本信息并退出。
- `--ll`: 设置日志级别 (debug, info, warn, error)，默认 `info`。
- `--lf`: 指定日志输出文件路径。
- `--lcf`: 控制台日志格式，可选 T(时间)/L(级别)/C(调用处)/F(函数)/M(消息)，默认 `LM`。

## 4. 使用示例

### 1. 初始化缓存（首次使用推荐）

使用内置字典生成缓存（add 模式）：

```bash
./decipher -m add -p builtin
```

### 2. 添加自定义字典到预计算库

将 `my_passwords.txt` 中的密码，并使用 salt=666 进行 hash 预计算并加入缓存：

```bash
./decipher -m add -p ./my_passwords.txt -s 666
```

### 3. 单个哈希解密

```bash
./decipher -i e10adc3949ba59abbe56e057f20f883e
```

### 4. 批量解密

从 `hashes.txt` 读取哈希列表进行解密，并将结果保存到 `result.csv`：

```bash
./decipher -i ./hashes.txt -o ./result.csv
```

### 5. 指定算法解密

只使用 MD5 算法进行解密：

```bash
./decipher -i e10adc3949ba59abbe56e057f20f883e -a md5
```

### 6. 使用动态算法解密

使用 bcrypt 动态算法进行解密（注意：动态算法只在静态算法解密失败后执行，或明确指定时执行）：

```bash
./decipher -i <bcrypt_hash> -a bcrypt -p ./custom_dict.txt
```

### 7. 加密模式

使用 MD5 算法加密明文 "123456"：

```bash
./decipher -m enc -i 123456 -a md5
```

### 8. 带 Salt 加密

使用多个算法加密明文 "password" 并添加 Salt "salt123"：

```bash
./decipher -m enc -i password -s salt123 -a md5,sha1,sha256
```

### 9. 哈希识别

识别哈希值的可能算法：

```bash
./decipher -m id -i e10adc3949ba59abbe56e057f20f883e
```

### 10. 导出结果为 JSON

```bash
./decipher -i ./hashes.txt -o ./result.json -O json
```

### 11. 禁用预计算破解

对所有算法都使用动态破解（不使用预计算缓存）：

```bash
./decipher -i ./hashes.txt --npc
```

### 12. 指定工作线程数

使用 8 个并发线程进行解密：

```bash
./decipher -i ./hashes.txt -w 8
```

## 5. 开发与贡献

### 核心优化点 (Recent Improvements)

- **Identify 接口**: 实现了基于 Hash 指纹的算法预筛选，避免了对不匹配算法的无效调用。
- **NeedSalt 接口**: 实现了对不需要 Salt 的算法（如 MD5 原生）的智能跳过，避免了由 Salt 列表引起的冗余计算。
- **策略预计算**: 在 `hash_cracker.go` 中引入 `CrackStrategy`，将复杂的判断逻辑移出热点循环，提升了核心破解路径的执行效率。
- **文件级过滤**: 在 `predb_cracker.go` 中实现了基于 `Identify` 的文件级跳过，大幅减少了无效 IO。
- **多阶段解密**: 实现了预计算缓存 → 动态哈希 → 加密解密的三级解密流程，提升成功率。

### 算法分类

- **静态算法**: 可以预计算缓存，解密速度快（如 MD5, SHA1, SHA256）
- **动态算法**: 无法预计算，只能实时验证（如 bcrypt）
- **加密算法**: 可逆加密算法，需要密钥进行解密（如 BASE64, DES, AES）
