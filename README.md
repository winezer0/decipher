# decipher

[简体中文](README.md) | [English](README.en.md)

decipher 是一个基于 Go 语言编写的高性能本地哈希解密工具。它利用预计算（彩虹表原理）的方式，通过构建本地哈希缓存库来实现快速的哈希查找与解密。支持多种常见的哈希算法，并内置了常用的弱口令字典。

## 1. 功能介绍

- **高性能解密**: 利用 Go 语言的并发特性，快速进行哈希计算和匹配。
- **静态哈希算法**: 内置 30+ 种静态哈希算法，涵盖 MD5, SHA 系列, MySQL, NTLM, MSSQL等。
- **动态哈希算法**: 支持bcrypt等明文和密文无对应关系的动态hash算法。
- **解密算法支持**: 支持BASE64、DES、AES等某些CMS的密码解密算法。
- **预计算缓存解密**: 支持将自定义字典和内置字典预先计算为哈希表（Cache），极大提升后续的解密速度。
- **动态计算解密**: 支持运行时动态验证哈希值，无需预计算所有可能的哈希组合。
- **Salt支持**: 支持带 Salt 的哈希计算和解密，可灵活配置 Salt 组合模式。
- **内置字典**: 仅集成部分简单常用弱口令，更多字典需要用户添加。
- **算法猜测**: 支持通过hash和salt解密从而实现算法猜测。
- **结果导出**: 支持将解密结果导出为 CSV 或 JSON 文件。

## 2. 程序运行逻辑与解密原理

decipher 的核心原理是**预计算缓存碰撞 + 实时hash计算 + 可逆算法解密**。

### 解密阶段详解

#### 阶段 1: 预计算缓存破解 (Predb Crack)

- **适用算法**: 静态哈希算法 (MD5, SHA1, SHA256等)
- **原理**: 使用预先计算的哈希缓存文件进行快速匹配
- **优势**: 速度极快，适合常见哈希算法
- **控制**:
  - 默认执行预计算破解
  - `--npc` 禁用预计算破解，对支持缓存的静态算法也使用动态破解
- **执行条件**:
  - 存在预计算算法且未被 `--npc` 禁用 → 执行预计算破解
  - 被 `--npc` 禁用 → 直接使用动态破解 (RunHashCrack)

#### 阶段 2: 动态哈希破解 (Dynamic Crack)

- **适用算法**:
  - 静态哈希 (计算速度快)
  - 动态哈希 (bcrypt等，明文密文无固定关系)
- **原理**: 使用字典文件进行实时哈希计算验证
- **优势**: 无需预计算，灵活性高
- **控制**:
  - `--ndc` 禁用动态破解
- **执行条件**:
  - 预计算破解失败后执行
  - 未被 `--ndc` 禁用
  - 包含静态或动态算法

#### 阶段 3: 加密解密阶段 (Decrypt)

- **适用算法**: 可逆加密算法 (BASE64, DES, AES等)
- **原理**: 使用密钥字典进行解密测试
- **优势**: 可解密某些CMS的加密密码
- **执行条件**:
  - 在预计算和动态破解失败后执行
  - 存在可逆加密算法

## 3. 命令行参数说明

### 常用命令速查

以 Linux/macOS 的 `./decipher` 为例；Windows PowerShell 可将可执行文件写作 `.\decipher.exe`。

```sh
# 查看帮助、版本和支持的算法
./decipher --help
./decipher --version
./decipher --list

# 识别哈希算法
./decipher id -i file:hashes.txt -o .

# 计算 MD5
./decipher enc -p str:123456 -a 'md5($pass)' -A

# 使用字典破解哈希；-p - 使用内置明文字典
./decipher dec -i file:hashes.txt -p file:words.txt -a 'md5($pass)' -A
./decipher dec -i file:hashes.txt -p -

# 追加用户字典，构建 MD5 预计算库
./decipher dict add -p file:words.txt
./decipher dict init -a 'md5($pass)' -A

# 去重预计算数据库，或清理缓存与失败记录
./decipher --dc
./decipher --cc
```

使用 `./decipher -h` 查看命令列表，使用 `./decipher enc -h`、`./decipher dict add -h` 等查看对应子命令的原生帮助。业务参数必须放在子命令后。

### 子命令

| 命令 | 职责 | 主要参数 |
| --- | --- | --- |
| `enc` | 计算明文的哈希或密文 | `-p`、`-s`、`-a`、`-A`、`-o`、`-O` |
| `dec` | 破解哈希或解密密文 | `-i`、`-p`、`-s`、`-a`、`-A`、`--npc`、`--ndc`、`-o`、`-O` |
| `id` | 识别可能的哈希算法 | `-i`、`-o`、`-O` |
| `dict add` | 仅追加内置明文和盐字典，不生成预计算库 | `-p`、`-s`，至少提供一个 |
| `dict init` | 仅生成或扩充预计算库，不追加内置字典 | `-p`、`-s`、`-a`、`-A` |

每次运行选择一个业务子命令。`dict init` 未指定 `-p` 或 `-s` 时分别读取对应内置字典；显式输入只用于本次预计算。init 仅处理标记支持预计算的静态算法，无符合算法时会报错。`dec` 可自动检查和生成所需预计算缓存。

日志、数据目录、查询和维护参数为全局参数，可放在子命令前后；`-w` 和前后缀参数仅适用于 `enc/dec/dict init`，`-R` 适用于五个业务命令，`--concat-symbol` 仅适用于 `dec`。不属于当前子命令的业务参数会报错。

### 基础输入输出

- `-i, --hashes`: 输入待破解、解密或识别的哈希值、密文或文件路径（每行一个）；加密明文通过 `-p` 提供。
- `-o, --output`: 指定输出目录路径（默认当前目录）。
- `enc`、`dec`、`id` 分别写入目录中的 `decipher.enc.csv`、`decipher.dec.csv`、`decipher.id.csv`；选择 JSON 时后缀为 `.json`。
- `-O, --output-type`: 指定输出格式，可选 `csv` 或 `json`（默认为 `csv`）。
- `enc` 的 CSV 包含 `algorithm,hash,salt,plaintext` 表头，JSON 为含同名字段的对象数组；字段由标准序列化器转义。

### 文件覆盖与缓存写入规则

| 文件 | 默认行为 |
| --- | --- |
| `decipher.enc.csv/json`、`decipher.dec.csv/json`、`decipher.id.csv/json` | 每次导出覆盖同名文件，不合并旧结果；不同格式的文件互不影响 |
| 失败记录（默认 `decipher.failure.csv`） | 本次有失败目标时覆盖；没有失败目标时不写入、不删除已有文件 |
| 成功结果缓存 `success.cache` | 追加新结果；已缓存命中沿用现有读取规则 |
| 内置明文、盐字典 | `dict add` 追加，不自动去重；内置字典缺失时由引擎初始化创建 |
| `cache_*.predb` | `dict init` 和 dec 的预计算生成沿用追加规则；`--dc` 可单独去重 |

### 各命令的输入数据格式

输入参数支持以下前缀：

| 前缀 | 含义 |
| --- | --- |
| `file:路径` | 从文件逐行读取数据，每行一条。 |
| `str:值` | 将值作为字面字符串输入。 |
| `gen:规则` | 按规则生成输入值。 |

不带前缀时，若路径存在则按文件读取，否则按字面字符串处理。一个参数可重复传入多个值，也可用逗号分隔；逗号也会拆分字符串和文件路径。`-p -` 和 `-s -` 分别选择内置明文和 Salt 字典，不表示从标准输入读取。

| 命令 | 输入参数 | 数据内容 |
| --- | --- | --- |
| `enc` | `-p` | 待计算的明文；可直接给值，也可传文件，每行一个明文。 |
| `enc` | `-s`（可选） | Salt/密钥值；可直接给值，也可传文件，每行一个值。 |
| `dec` | `-i` | 待破解的哈希或密文；可直接给值，也可传文件，每行一个目标。行格式为 `哈希`、`哈希:Salt` 或 `哈希:Salt:其他字段`；默认分隔符为 `:`，可用 `--concat-symbol` 修改。解析只使用哈希和 Salt，第三段及后续字段会被忽略。 |
| `dec` | `-p`、`-s`（可选） | 候选明文和 Salt/密钥；可直接给值或传入每行一个值的文件。 |
| `id` | `-i` | 待识别的哈希；可直接给值，也可传文件，每行一个哈希。 |

例如，`enc -p str:123456` 计算单个明文；`dec -i file:hashes.txt` 从文件读取目标；`id -i str:5f4dcc3b5aa765d61d8327deb882cf99` 识别单个哈希。

使用时按子命令提供对应输入：`enc` 从 `-p` 读取待计算的明文，需要盐或密钥时再通过 `-s` 提供；`dec` 从 `-i` 读取待解密目标，再通过 `-p` 和 `-s` 提供候选明文及盐/密钥；`id` 只需通过 `-i` 提供待识别的哈希。单个值可用 `str:值` 直接传入，批量数据可放入 `file:路径` 指定的文件，每行一条。

不增加追加或覆盖开关。输出目录应事先存在；导出失败返回非零退出码。覆盖写入不提供原子替换保证。

### 缓存构建与字典管理

- `-p, --plains`: 指定自定义明文字典文件路径或直接输入字典字符串。
  - 在 `dict add` 中：追加内置明文字典；在 `dict init` 中：用于生成预计算数据。
  - 在 `dec` 模式下：作为动态破解的字典源。
  - 在 `enc` 模式下：作为加密用的明文字典。
- `-s, --secrets`: 指定 Salt/密钥 字符串或包含 Salt 的文件路径。
  - 在 `dict add` 中：追加内置盐字典；在 `dict init` 中：与明文字典组合生成预计算数据。
  - 在 `dec` 模式下：作为动态破解的 Salt/密钥 字典。
  - 在 `enc` 模式下：作为加密用的 Salt/密钥。
- `--sp`: 在使用 Salt 前添加前缀字符串（默认为空）。
- `--ss`: 在使用 Salt 后添加后缀字符串（默认为空）。
- `--pp`: 在使用明文密码前添加前缀字符串（默认为空）。
- `--ps`: 在使用明文密码后添加后缀字符串（默认为空）。

前缀、后缀和日志参数使用现有名称 `--sp/--ss/--pp/--ps/--ll/--lf/--lcf`，不提供额外的长名称别名。

- `-w, --workers`: 指定并发工作线程数（默认为 0，自动适配 CPU 核心数）；正整数指定并发数，负数会报错。
- `-C, --cc`: 清空预计算库、临时字典目录及配置的失败记录，完成后退出，不再执行业务子命令。
- `-D, --dc`: 对 hash 预计算缓存文件进行去重整理，完成后退出，不再执行业务子命令。
- `-R, --rr`: 操作成功或失败后均清理本次生成的临时字典；清理失败返回非零退出码。不指定时保留临时文件。
- `--npc`: 禁用预计算缓存破解（predb），对支持缓存的静态算法也使用动态破解。
- `--ndc`: 禁用动态计算破解（dynamic crack）。

显式使用 `file:路径` 时，文件不存在、不可读取或不是普通文件会立即报错，不会回退到内置字典。未使用前缀时仍保留“优先文件，否则按字符串处理”的规则。

执行或结果导出失败时返回非零退出码。输入有效但未找到匹配明文属于正常完成，不视为程序执行失败。

### 算法控制

- `-a, --algos`: 指定使用的哈希算法关键字（例如 `md5`, `sha1`, `bcrypt`）。支持部分匹配，会自动匹配包含指定关键字的所有算法。如果不指定，默认使用所有可用算法。
- `-A, --precise`: 按算法完整名称精确匹配，与 `-a` 配合使用，例如 `-a 'md5($pass)' -A`。
- `-L, --list`: 列出当前支持的所有哈希算法。

## 4. 使用示例

### 1. 初始化缓存（首次使用推荐）

使用内置字典生成预计算缓存：

```bash
./decipher dict init -a 'md5($pass)' -A
```

### 2. 添加自定义字典到预计算库

先追加内置明文、盐字典，再单独生成预计算库：

```bash
./decipher dict add -p file:./my_passwords.txt -s str:666
./decipher dict init -a md5
```

### 3. 单个哈希解密

```bash
./decipher dec -i e10adc3949ba59abbe56e057f20f883e
```

### 4. 批量解密

从 `hashes.txt` 读取哈希列表进行解密，并将结果保存到当前目录的 `decipher.dec.csv`：

```bash
./decipher dec -i file:./hashes.txt -o .
```

### 5. 指定算法解密

只使用 MD5 算法进行解密：

```bash
./decipher dec -i e10adc3949ba59abbe56e057f20f883e -a md5
```

### 6. 使用动态算法解密

使用 bcrypt 动态算法进行解密（注意：动态算法只在静态算法解密失败后执行，或明确指定时执行）：

```bash
./decipher dec -i 'str:<bcrypt_hash>' -a bcrypt -p file:./custom_dict.txt
```

### 7. 加密模式

使用 MD5 算法加密明文 "123456"：

```bash
./decipher enc -p 123456 -a md5
```

### 8. 带 Salt 加密

使用多个算法加密明文 "password" 并添加 Salt "salt123"：

```bash
./decipher enc -p password -s salt123 -a md5,sha1,sha256
```

### 9. 哈希识别

识别哈希值的可能算法：

```bash
./decipher id -i e10adc3949ba59abbe56e057f20f883e
```

### 10. 导出结果为 JSON

结果保存到当前目录的 `decipher.dec.json`：

```bash
./decipher dec -i file:./hashes.txt -o . -O json
```

### 11. 禁用预计算破解

对所有算法都使用动态破解（不使用预计算缓存）：

```bash
./decipher dec -i ./hashes.txt --npc
```

### 12. 指定工作线程数

使用 8 个并发线程进行解密：

```bash
./decipher dec -i ./hashes.txt -w 8
```

## 5. 开发与贡献

### 核心优化点 (Recent Improvements)

- **Identify 接口**: 实现了基于 Hash 指纹的算法预筛选，避免了对不匹配算法的无效调用。
- **NeedSalt 接口**: 实现了对不需要 Salt 的算法（如 MD5 原生）的智能跳过，避免了由 Salt 列表引起的冗余计算。
- **策略预计算**: 在 `hash_cracker.go` 中引入 `CrackStrategy`，将复杂的判断逻辑移出热点循环，提升了核心破解路径的执行效率。
- **文件级过滤**: 在 `predb_cracker.go` 中实现了基于 `Identify` 的文件级跳过，大幅减少了无效 IO。
- **多阶段解密**: 实现了预计算缓存 → 动态哈希 → 加密解密的三级解密流程，提升成功率。

### 算法分类

- **静态算法**: 可以预计算缓存，解密速度快（如 MD5, SHA1, SHA256）
- **动态算法**: 无法预计算，只能实时验证（如 bcrypt）
- **加密算法**: 可逆加密算法，需要密钥进行解密（如 BASE64, DES, AES）
