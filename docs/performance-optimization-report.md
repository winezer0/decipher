# 性能优化验收报告

本轮性能优化从基线 `981774e` 开始，六项实现依次提交，最后的测试边界补充提交为 `c21421b`。相关提交：`b28f284`、`934db0d`、`874bcbd`、`8835646`、`6addc40`、`b1b3441`。

## 结果概览

| 优化 | 代表性场景 | 优化前 | 优化后 | 变化 |
|---|---|---:|---:|---:|
| 降低大目标列表的算法引用分配 | SHA-256 准备，100000 个目标 | 10.12 ms，300004 allocs | 6.19 ms，1182 allocs | 耗时约 -39%，分配次数约 -99.6% |
| 同算法目标共享候选摘要 | 全流程 SHA-256，1000 目标 × 1000 候选 | 18.50 ms | 1.83 ms | 约 -90% |
| 批次共享盐前后缀 | 20 个候选 × 10000 个盐 | 26.39 ms，约 5.08 MB/op | 24.56 ms，约 619 KB/op | 耗时约 -7%，分配字节约 -88% |
| 跳过无匹配目标的任务派发 | 10000 个候选的拒绝模式 | 5.86 ms | 0.40 ms | 约 -93% |
| 多字典命令复用不可变策略 | 8 个字典 × 100000 个目标 | 181.84 ms，约 176 MB/op | 133.53 ms，约 22.1 MB/op | 耗时约 -27%，分配字节约 -87% |
| 合并快速进度更新 | 100000 行真实字典，1 Worker | 70.58 ms | 66.10 ms | 约 -6% |

整体流水线另行以基线和最终版本比较：SHA-256 的 100000 目标 × 1 候选由 16.47 ms 降至 7.98 ms；单目标单候选为 3.98 μs 与 3.90 μs。单场景结果不代表所有算法、输入和机器的表现。

## 测量方法与限制

测量机器为 Windows amd64、Go 1.26.4、AMD RYZEN AI MAX+ 395。内部基准设置 CPU=4，前后版本交替运行 5 轮，常规每轮基准窗口 80 ms；疑似波动或回退时增加 300/500 ms 复测。最终 CLI 对比覆盖 28 种场景，每个版本、每种场景 15 次独立进程运行，共 840 个样本，并记录耗时和峰值内存。

短命令会受进程启动、文件和控制台成本影响。测量显示部分小输入 CLI 场景变慢或波动，端到端峰值内存大致持平；因此不把内部基准加速比例外推为所有工作负载的收益。共享盐任务元数据使部分小场景增加约 48 B/op，批次共享主要改善大批量且有盐前后缀的输入。

第二项的较长复测发现初版 Worker 栈帧回退。将分组摘要处理提取为独立函数后，普通 Worker 栈帧由 840 字节缩至 752 字节；单目标和长输入复测回到基线附近或更快。最终数据包含这项修正。

## 功能与验证

优化保留目标和算法顺序、重复目标结果、自定义或包装算法回调、原始盐字段、跨命令配置隔离、输入读取、取消和进度字节累计。共享的候选摘要、盐前后缀及跨字典策略仅在确认算法为内置纯算法时启用。运行时候选结果缓存未重新引入。

每项变更均经过全量测试、race、vet、编译和差异检查。新增边界测试还验证了混合算法回退、共享盐预处理阈值和输入盐不可变。

从仓库根目录运行：

```bash
go test ./...
go test -race ./...
go vet ./...
go build -o bin/decipher.exe ./cmd/decipher
```

逐轮原始采样文件此前保存在本地 `bin/` 目录（该目录由 `.gitignore` 排除）；本报告记录复核后的代表性数值。测试和基准运行方式见 [测试指南](testing.md)。
